# Legacy save import fixtures

The three ROM inputs are original, non-commercial test images generated by
[`generate-roms.py`](generate-roms.py). The script builds them from zero-filled
byte arrays and a small set of documented header, entry-point, and save-type
bytes. It uses only the Python standard library and reproduces the committed
ROM files byte for byte. No commercial game data or third-party ROM source is
used.

The generator and generated ROMs are covered by the repository's root
[`LICENSE`](../../../../LICENSE) (MIT). The `.srm` and `.rtc` files are raw
outputs from the matching packaged RetroArch cores when run against these test
images; they are test data, not commercial save data. They are distributed
under the same repository license. The Gambatte RTC output contains a
clock-derived value, so a new run may produce a different RTC hash while
preserving the same 8-byte raw format.

## Reproduce

Generate the ROM inputs on a host:

```sh
python3 system/banana-retro/tests/legacy-fixtures/generate-roms.py /tmp/legacy-fixtures/roms
```

To regenerate the raw save outputs, run this from a BananaOS AArch64 QEMU guest
with the packaged cores installed at `/usr/lib/libretro`:

```sh
sh system/banana-retro/tests/legacy-fixtures/generate-saves.sh \
    /usr/lib/libretro /tmp/legacy-fixtures
```

The script runs each packaged core for 20 frames with null video, audio, and
input drivers. It checks the expected SRAM/RTC lengths and prints SHA-256
hashes. For the committed core compatibility capture, the core hashes are:

| Profile | Reported core name | ROM | SRAM bytes | RTC bytes | Packaged core SHA-256 |
| --- | --- | --- | ---: | ---: | --- |
| mGBA/GBA | `mGBA` | `mgba.gba` | 131072 | 0 | `1a3ab69ab871cdca7abc6e838bcd57a5601d9a309c46ed64c74b44f638c96242` |
| Gambatte/GB | `Gambatte` | `gambatte.gb` | 32768 | 8 | `0ea14782f81a1124c09776e7abe41ac4d6f52f8fb2845b070c814b790162b2d8` |
| FCEUmm/NES | `FCEUmm` | `fceumm.nes` | 8192 | 0 | `c92d81870053800371cd0fa44bc217d3f9c51995331eb19de9a83b63d342a286` |

These packaged cores ran the generated content in BananaOS QEMU with
`--max-frames=20`; RetroArch emitted the raw files in the library-name
directories shown here. This is target-software evidence, not physical-device
or exFAT durability qualification.
